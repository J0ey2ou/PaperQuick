# 前三批研究工作台实施范围

本次按用户授权实施以下三批，第四批团队协作与跨设备同步留待后续。

1. 日常效率与可靠性：每附件阅读现场恢复、保存智能视图、课题问题/待办/阅读队列、校验完整备份与恢复到新目录、持久化后台任务中心。
2. 可检索证据：真正逐页全文索引与覆盖率、文内搜索、可配置本地 OCR、可回源证据卡、带证据的可编辑比较矩阵。
3. 研究输出：限定范围的跨文献 AI（发送前预览、引用校验）、证据驱动综述提纲与导出、引用审计、摘要/全文两阶段筛选及统计、带导入预览的完整课题交接包。

## 验收边界

- 使用现有文献库增量扩展，保存操作在事务中读取最新数据，避免不同模块覆盖无关字段。
- 备份使用 SQLite snapshot，逐文件 SHA256；恢复与交接导入不覆盖正在使用的库。禁止把 API 密钥打入课题交接包。
- 任务可取消，失败原因可查看，重启后将未完成任务标为中断；后台线程不访问 Tk。
- 索引覆盖全部可提取页面，扫描页与缺失文件可见；段落定位不能称为 PDF 页码；OCR 缺引擎时明确提示，不自动下载或上传。
- AI 仅在用户点击发送后调用其已配置接口；模型输出与原文分离，引用 ID/原文片段校验不等于结论正确性验证。
- 全部验证通过后台脚本与隔离临时库进行，不运行前台自动化、真实付费 AI 请求或真实 Word 操作。
- 发布与本地更新继续遵循 AGENTS.md 的签名提交、公开更新清单、SHA256 和退出后替换约束；不合并主分支。

## 模块分工

- `workspace_tasks.py` / `library_backup.py` / `maintenance_ui.py`：任务与备份。
- `fulltext_index.py` / `search_ui.py` / `reading_resume.py`：检索、OCR、阅读恢复。
- `research_store.py` / `research_ui.py`：证据、矩阵、提纲、筛选。
- `workspace_state.py` / `workspace_ui.py`：智能视图、课题工作台。
- `project_ai.py` / `project_ai_ui.py`：跨文献 AI 与来源审核。
- `project_handoff.py` / `project_handoff_ui.py`：完整课题交接与隔离导入。

各模块需单元与隐藏界面验证，最终执行完整后台回归、冻结程序验证及真实更新清单验证。
